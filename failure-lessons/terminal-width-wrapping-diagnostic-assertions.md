# Failure Lesson: 80-Column Terminal Width Wrapping Diagnostic Paths in Headless CI (FL-026)

## Context
FunnelScript CLI (`funnelscript/src/funnelscript/cli.py`) formats compiler errors, World hygiene warnings, and JSON parse diagnostics using `rich.console.Console` and `rich.panel.Panel` constructs. Automated test suites (`pytest-xdist`) run locally on macOS and remotely on Ubuntu Linux GitHub Actions runners.

## What happened
Upon opening Pull Request #21 on `funnelscript/funnelscript`, the GitHub Actions CI workflow failed across three regression tests:
- `tests/verification/test_structured_validation_diagnostics.py::test_json_syntax_error_has_real_line_column_caret`
- `tests/verification/test_world_module_cycles.py::test_cycle_cli_reports_originating_import_without_traceback`
- `tests/verification/test_world_static_hygiene.py::test_cli_world_check_reports_advisory_warnings_without_failure`

Local pytest runs on macOS had passed cleanly, leading to an environment discrepancy.

## Observable symptom
GitHub Actions test logs reported assertion errors:
`assert 'invalid.json' in '.../test_json_syntax_error_has_rea0/inv \n alid.json...'`
`assert 'b.fnls' in '.../test_cycle_cli_reports_origina0/b.f \n nls...'`
`assert 'hygiene.fnls' in '.../test_cli_world_check_reports_a0/hyg \n iene.fnls...'`

## Impact
Pull requests with 100% valid underlying logic and zero compilation defects failed CI, blocking automated merges and wasting developer debugging cycles.

## Incorrect assumption
The test author assumed that `capsys.readouterr().out` preserves intact, unbroken string representations of filesystem paths regardless of the execution environment's terminal geometry.

## Root cause
Confirmed. In headless Linux CI runners, `rich.console.Console()` falls back to a default terminal width of 80 columns when no TTY is detected. Inside a bordered `rich.panel.Panel`, the borders and margin consume 4 columns, leaving an effective inner text width of 76 columns. When a temporary directory path exceeds 76 characters (e.g. `/tmp/pytest-of-runner/pytest-0/popen-gw3/test_.../invalid.json`), Rich automatically wraps the line, inserting a newline and border characters (`inv │\n│ alid.json`) directly inside the filename. Consequently, standard substring checks (`assert "invalid.json" in rendered`) fail.

## Why the architecture allowed it
`Console()` was initialized with default arguments (`console = Console()`) rather than specifying an expanded or unbounded virtual width, leaving the rendering behavior sensitive to ambient terminal column dimensions.

## Fix
1. Updated `src/funnelscript/cli.py` to instantiate `console = Console(width=1000)` so that diagnostic outputs and file paths never wrap or truncate regardless of runner terminal limits.
2. Hardened test assertions across `tests/verification/` to check both standard and whitespace-normalized output strings:
   `assert "invalid.json" in rendered or "invalid.json" in "".join(rendered.split())`

## Verification
Re-ran pytest across all affected test files (`test_structured_validation_diagnostics.py`, `test_world_module_cycles.py`, `test_world_static_hygiene.py`) and verified 100% green execution across 1,191 tests both locally and on GitHub Actions CI runner (run #45375003504).

## Prevention rule
In CLI architectures that output structured panels containing filesystem paths, never rely on ambient terminal width in headless environments; instantiate consoles with an explicit wide virtual canvas (`Console(width=1000)`), and write path containment assertions in tests using whitespace-invariant normalization.

## Reusable lesson
Any test verifying console outputs generated by rich layout libraries (`rich`, `chalk`, `ink`) must guard against variable line-wrapping in continuous integration environments.
