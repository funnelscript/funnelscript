# Phase 007F: successful rename is not a durable acknowledgement

A pre-rename exception preserves the old checkpoint in the declared single-writer model, but a post-rename directory synchronization failure leaves an ambiguous physical durability state. Tests inject failures at temporary file creation, file synchronization, namespace replacement and parent directory synchronization. A coordinator must not convert these exceptions into an unqualified SUCCESS. Instead, the caller inspects persisted canonical evidence, revalidates original World/policy and compares a trusted prior or candidate receipt before retrying. An unanchored SHA-256 value remains integrity metadata, not operator authentication, rollback resistance, multi-writer arbitration or proof of physical power-fail durability.
