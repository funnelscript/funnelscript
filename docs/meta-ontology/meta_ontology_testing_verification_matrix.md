# Meta-Ontology & Traits: Testing & Verification Strategy

**Document 4 of 4** | **Scope:** What to Test, Formal Invariants, Property Tests & Release Gates

---

## 1. Testing Philosophy

A Meta-Ontology system cannot be verified by testing a single hardcoded scenario. You must prove two stronger properties:
1. **Soundness:** Any custom object defined by any user that passes the Trait checker is *guaranteed* to obey FunnelScript's dimensional, financial, and mass-conservation laws at runtime.
2. **Composability:** Independently authored `fpm` packages sharing `core/commerce_traits` compose cleanly without semantic drift, double-counting, or ledger imbalances.

---

## 2. The 6 Mandatory Verification Suites

### Suite 1: Trait Conformance & Negative Compiler Tests
* **Location:** `tests/fixtures/meta-ontology/` & `tests/test_trait_conformance.py`
* **What to Test:**
  * **Valid Lowering:** Custom entities implementing 1, 2, or all 5 Core Traits compile cleanly and pass `funnelscript fmt` round-trip idempotency.
  * **Negative Cases (Must Fail Statically with `FNL-O3xx`):**
    * Missing required Trait field or lifecycle handler (`FNL-O301`).
    * Wrong dimensional unit on a Trait field—e.g., passing `Duration` where `FinancialBinding` expects `Currency<USD>` (`FNL-O302`).
    * Unbalanced double-entry posting inside a `FinancialBinding` handler (`FNL-O303`).
    * Ambiguous Trait diamond collision without disambiguation (`FNL-O304`).
    * Attempting unsupported multi-level class inheritance (`FNL-O305`).

### Suite 2: Lowering Equivalence & Determinism Tests
* **Location:** `tests/verification/test_lowering_equivalence.py`
* **What to Test:**
  * **Behavioral Equivalence:** A strategy written using high-level `entity ... implements Trait` syntax must produce **bit-for-bit identical** event traces, RNG draws, and SHA-256 ledger hashes as the equivalent hand-written low-level `.fnls` world.
  * **Hash-Seed Independence:** Running lowered entity simulations across multiple randomized `PYTHONHASHSEED` values yields identical outputs.
  * **Snapshot & Resume:** Splitting a simulation containing custom entities at $t_{\text{split}}$, calling `snapshot()` / `restore()`, and finishing to $T$ matches an uninterrupted $0 \to T$ run identically.

### Suite 3: Cross-Package Interoperability Tests (The Ecosystem Proof)
* **Location:** `tests/test_cross_package_interop.py`
* **What to Test:**
  * Author two completely separate mock `fpm` packages that do **not** know about each other—only sharing `core/commerce_traits`:
    * `pkg_a/paid_acquisition` (produces `Order` entities implementing `std.FinancialBinding` + `std.Attributable`).
    * `pkg_b/retention_engine` (consumes any entity implementing `std.CustomerCohort` + `std.FinancialBinding`).
  * Import both in a single consumer `.fnls` strategy file and assert:
    * Clean compilation and dimensional linting across package boundaries.
    * Single unified `LedgerAccount` trial balance ($\sum \text{Debits} = \sum \text{Credits}$ at every tick).
    * Zero dropped or duplicated entities across the handoff boundary.

### Suite 4: Property-Based Conservation Fuzzing (Hypothesis)
* **Location:** `tests/verification/test_meta_ontology_invariants.py`
* **What to Test:**
  * Generate arbitrary valid graphs of custom `Pool`, `Flow`, `CapacityGuard`, and `LedgerAccount` entities using `hypothesis` and verify universal invariants across thousands of random seeds:
    1. **Non-Negativity Invariant:** $\forall t,\; Q_{\text{pool}}(t) \ge 0$.
    2. **Mass Conservation Invariant:** Total created entities minus exited/terminated entities equals exact sum of all active pools + in-transit delay queues:
       $$
       \sum Q_{\text{active}}(t) + \sum Q_{\text{in\_transit}}(t) = Q_{\text{initial}} + \text{Created}(t) - \text{Exited}(t)
       $$
    3. **Capacity Ceiling Invariant:** No `CapacityGuard` ever processes more units per tick than its declared limit $C_{\max}$.
    4. **Financial Conservation Invariant:** $\sum \text{Debits}_c(t) - \sum \text{Credits}_c(t) = 0$ for every currency $c$ at every tick $t$, with zero floating-point drift.

### Suite 5: Data-to-Object Mapping & Provenance Tests (`Ingestable`)
* **Location:** `tests/test_object_mapper.py`
* **What to Test:**
  * Hydrating custom entities (`CODParcel`, `SalesLead`) from messy real-world CSV and mock Stripe/Segment JSON fixtures via `mapping.toml`.
  * **Rejection of Bad Data:** Missing required fields, invalid currency codes, or negative durations route cleanly to the Dead-Letter Queue (DLQ) with exact row-level diagnostics—never silently inserting `0` or `NaN`.
  * **Idempotent Replay:** Re-ingesting the same dataset twice produces zero duplicate entity instantiations or ledger postings.
  * **Full Traceability:** Every ledger posting generated by a hydrated entity traces back via `provenance.py` to its exact `source_file_hash` and `row_id`.

### Suite 6: Zero-Overhead Performance Benchmark
* **Location:** `scripts/benchmark_meta_ontology.py`
* **What to Test:**
  * Compare execution time and peak memory of a `100,000`-event simulation using Trait-based `entity` definitions vs. raw low-level `.fnls` rules.
  * **Hard Gate:** Overhead of lowered Meta-Ontology entities MUST be $\le 5\%$ in wall-clock runtime and $\le 5\%$ in peak memory, proving zero runtime reflection tax.
